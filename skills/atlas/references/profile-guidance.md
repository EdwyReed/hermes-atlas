# Profile-specific recipes

Shared public instructions cannot contain private session evidence, editorial
plans, credentials or another profile’s history. During approved migration,
`rollout.py` preserves each absorbed skill and its references under the SAME
profile home at:

`$HERMES_HOME/plugin-data/atlas/references/profile-guidance/INDEX.md`

Read that index with the file tool when the request depends on a prior recipe.
It records original source paths/profile context. `source.md` is the preserved
skill body and sibling references remain together. It is deliberately outside
Git and is not another registered skill. Do not read another profile’s guidance.
If absent, no migration occurred or the profile had no extra recipes; do not
invent defaults from another person’s private material.

The bundled skill and live schema supersede retired execution routes. Preserve
specific artistic/composition/denoise/LoRA requirements as requirements even when
the current engine cannot represent them. Historical CLI paths, database queries
and old native scripts in source references are maintenance evidence, never
permission to bypass Engine. Keep artistic `danbooru` and other non-Atlas skills
separate. Specialist maintenance skills are not absorbed just because their name
contains Atlas. Shared symlinked specialist instructions are left unchanged and
listed for operator review rather than editing another profile’s target.
